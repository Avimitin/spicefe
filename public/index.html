GETTING STARTED

Set up spice2x in three steps

Enable the API stream on your gaming PC, allow LAN access, then connect from this device.

  1. Configure spice2x

    Choose either spicecfg or command-line options. Both enable the same API stream, so you only need one.

    Option B

    Command line

    Add these options when launching the game:

    spice64.exe -api 1337 -apistream

    To protect API commands with a password, append -apipass your-password and enter the same password in spicefe.

  2. Prepare the local network

    Connect this device and the gaming PC to the same LAN. In Windows Firewall, allow spice64.exe on Private networks.

    Find the gaming PC address Run ipconfig in Command Prompt and note the IPv4 Address for the active network adapter.

  3. Connect with spicefe

    Enter that IPv4 address as Host. Use the same API port and password configured in spice2x, then leave Format and Screen on Auto for the first connection.

Recommended starting settings

  • Auto format prefers H.264, which uses much less battery and bandwidth than MJPEG.
  • Auto screen selects the subscreen when the game provides one.
  • Start at 30 FPS and quality 70. Lower them if Wi-Fi is slow or the game is affected.

Quick troubleshooting

  • If both API and video fail, recheck the PC address, API port, spice2x version, and Windows Firewall.
  • If API connects but video fails, disconnect other viewers; spice2x allows one viewer per screen.
  • On iPhone or iPad, use Share → Add to Home Screen for a fullscreen app experience.

Browser connection setup

spice2x serves its stream over your local network without TLS. Choose your device and browser below so spicefe can reach it.

Type the full address beginning with http://

Do not enter only the domain name. Address-bar autocomplete can reuse your HTTPS visit and put you back in the blocked mode.

http://spicefe.avimit.in/

After loading it, inspect the address bar and verify that the address begins with http://. A “Not secure” label is expected.

LOCAL DEPLOYMENT

Serve spicefe on your LAN

Run the static page on a computer you control when a public hostname is forced to HTTPS or you prefer a fully local setup.

The Windows release is the simplest route

It needs no installation or administrator access. The included helper serves only the extracted spicefe files and downloads nothing when it runs.

Windows helper Nix Open on a device Operate & update

WINDOWS 10 & 11

Use the release ZIP

Recommended

Run this on the gaming PC, or on another Windows PC that stays on the same home network.

  1. Download the newest spicefe ZIP and its matching .sha256 file. Open GitHub Releases
  2. Extract the entire ZIP into a normal folder. Do not run files from inside the ZIP preview.
  3. Double-click serve.bat. A terminal opens, starts port 45000, and opens a local test page.
  4. If Windows Firewall asks, allow Private networks only. Do not allow Public networks.
  5. Keep the terminal open while using spicefe; press Ctrl+C or close it to stop serving.

Optional: verify the downloaded ZIP in PowerShell and compare the result with the .sha256 file:

Get-FileHash .\spicefe-vX.Y.Z.zip -Algorithm SHA256
serve.bat uses Windows PowerShell 5.1 and .NET already included with Windows. It does not install a service, edit firewall rules, or request elevation.

LINUX & MACOS

Run the reproducible Nix build

Nix flake

Use a repository checkout when Nix is available on a computer that your phone or tablet can reach.

git clone https://github.com/Avimitin/spicefe.git
cd spicefe
nix flake check
SPICEFE_BIND=0.0.0.0 SPICEFE_PORT=45000 nix run
  1. For a stable deployment, check out a release tag before running the checks.
  2. Nix builds the same pinned static site used by CI and supplies the Python server; no global npm install is needed.
  3. Leave the terminal open. Ctrl+C stops the server.
0.0.0.0 makes the page reachable from the LAN. Keep the machine firewall limited to trusted/private networks.

PHONE OR TABLET

Open the local page

HTTP on your LAN

Use the LAN address

On the phone or tablet, manually enter a cyan address printed by the Windows helper, such as http://192.168.1.50:45000/. Include http:// and the port.

Do not use 127.0.0.1

That address means “this device.” It works in the gaming PC's test browser but points back to the phone when entered on the phone.

Keep one trusted LAN

Both devices must be on the same network. Disable Wi-Fi client isolation, guest isolation, or AP isolation if the page cannot be reached.

A local-IP page has its own browser storage. Add the spice2x connection again the first time you use it; later visits keep that saved profile on the same device and address.

DAILY USE

Troubleshoot, change ports, and update

The page does not open

First test the 127.0.0.1 address on the server PC. Then recheck the cyan LAN address, Windows Private-network firewall access, the shared Wi-Fi, and client isolation.

The page opens, but streaming fails

Local deployment is already working. Recheck spice2x API Video Stream Server, its API port and password, the minimum spice2x version, and the separate spice2x firewall ports.

Use another page port

Run serve.bat 8080 from Command Prompt, or change SPICEFE_PORT for Nix. Use that same page port in the browser address; it does not change the spice2x API port.

Update safely

Stop the old server, download and verify the new release, extract it to a new folder, and start its helper. Browser profiles remain saved because the address and port are unchanged.

Using another static server

Advanced users may serve the Nix result or committed public directory over HTTP. Bind only to the trusted LAN, preserve normal JavaScript and WOFF2 MIME types, and open index.html through HTTP—not file://.

Keep the server private

The helper is designed for a trusted home LAN, not the public Internet. Allow only Private networks, do not port-forward it through your router, and stop it when it is no longer needed.
